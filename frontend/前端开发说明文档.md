# 前端开发说明文档

## 1. 项目定位

`frontend/` 是 `war_news_bias_detection` 的本地可视化前端，目标是提供两类能力：

1. 在浏览器或桌面壳中展示评估结果与样例回放。
2. 为未来的本地推理桥接预留交互入口。

当前项目更接近“本地演示应用”而不是传统在线网站：

- 页面大量依赖仓库内的本地数据文件。
- 样例图片不是 CDN 资源，而是仓库内的本地图片。
- Tauri 已接入壳层，但 Rust 侧业务桥目前仍是占位实现。

## 2. 技术栈

- `Vite 5`

## 5. 数据流说明

### 5.1 前端直接消费的数据

前端运行时主要读取两个文件：

- `public/demo/eval_metrics.json`
- `public/demo/eval_cases.json`

这两个文件由脚本 [scripts/sync-local-demo-data.mjs](./scripts/sync-local-demo-data.mjs) 生成。

### 5.2 数据生成来源

脚本会读取：

- `outputs/stage2_v3/eval_predicted_obs_report.json`
- `outputs/stage2_v3/eval_predicted_obs_predictions.jsonl`
- `data/processed/texts/articles_texts/*.json`

然后把结果整理成前端可直接展示的结构化 JSON。

### 5.3 样例加载流程

样例加载入口见 [src/services/cases.ts](./src/services/cases.ts)。

流程如下：

1. 前端通过 `fetch("/demo/eval_cases.json")` 读取样例。
2. 失败时回退到 `src/data/mockCases.ts`。
3. 页面根据样例中的 `imagePath`、正文和结果结构进行展示。

## 6. 分析台当前逻辑

分析逻辑入口见 [src/services/analysis.ts](./src/services/analysis.ts)。

当前逻辑分为三条路径：

- `Tauri` 桌面模式：优先走真实本地推理桥。
- `Vite dev` 浏览器开发模式：通过 Vite 本地中间件直接调用 Python `infer_stream.py`。
- 纯静态浏览器模式：保留“演示级流程回放 + 启发式占位”。

纯静态浏览器模式下：

- 如果当前输入能匹配到样例，则优先回放样例结果。
- 如果没有命中样例，则生成启发式 Stage 1 / Stage 2 占位结果。
- 历史记录和草稿通过 `localStorage` 保存。

当前已实现：

- 输入草稿缓存
- 最近分析历史缓存
- 阶段式流状态展示
- 样例回放
- Tauri 调 Rust / Python 命令链
- 调 Python 模型真实推理
- `npm run dev` 下通过 Vite 本地桥调用真实 Python 推理
- `infer_stream.py` 阶段事件输出

当前未实现：

- token 级流式生成

补充：

- 当前 `Tauri` 桌面壳已新增真实本地推理桥，桌面模式下分析页会优先调用 Rust 命令，再由 Rust 执行仓库根目录下的 `infer.py --stage full`。
- 默认 adapter 为 `outputs/stage2_v3/final_adapter`。
- Python 可执行路径解析顺序为：
  1. 环境变量 `WAR_NEWS_BIAS_PYTHON`
  2. `/root/miniconda3/envs/news_bias_312/bin/python`
  3. `PATH` 中的 `python`
- 浏览器 `dev` 模式会优先走真实本地推理；只有纯静态浏览器环境才回退到演示级结果。

## 7. 图片显示机制

图片相关逻辑见 [src/utils/imagePreview.ts](./src/utils/imagePreview.ts)。

### 7.1 当前使用的路径策略

样例 JSON 中的 `imagePath` 不再保存机器相关的绝对路径，而是保存“相对仓库根目录”的路径，例如：

```txt
data/processed/imgs/war_imgs_total/bethenny-frankel-getty.jpg
```

这个路径由 [scripts/sync-local-demo-data.mjs](./scripts/sync-local-demo-data.mjs) 生成。

### 7.2 浏览器开发模式

在 `npm run dev` 下：

- Vite 通过 `__REPO_ROOT__` 注入当前仓库根目录。
- 前端把相对路径拼成绝对路径。
- 再通过 `/@fs...` 访问本地文件。

相关配置见 [vite.config.ts](./vite.config.ts)。

注意：

- `server.fs.allow` 已显式允许读取仓库根目录。
- 如果这个配置缺失，浏览器会报 `403 Restricted`。

### 7.3 Tauri 桌面模式

在 Tauri 中：

- 前端仍然先把相对路径拼成当前仓库内的绝对路径。
- 再调用 `@tauri-apps/api/core` 的 `convertFileSrc(...)` 生成可显示 URL。

### 7.4 重要限制

这套方案成立的前提是：

- 整个 `war_news_bias_detection` 仓库一起迁移。
- `frontend/` 与 `data/` 的相对位置不变。

如果只迁移 `frontend/`，图片路径会失效。

## 8. Vite 配置说明

配置见 [vite.config.ts](./vite.config.ts)。

当前有三类关键配置：

1. 注入 `__REPO_ROOT__`
   用于把仓库相对路径解析为当前机器上的绝对路径。
2. `server.fs.allow`
   允许 dev server 读取仓库根目录内、但位于 `frontend/` 之外的文件。
3. `globalThis.crypto` 兼容补丁
   这是为了兼容当前旧环境里的 Node 运行时。

## 10. Tauri 当前状态

Rust 入口见 [src-tauri/src/main.rs](./src-tauri/src/main.rs)。

当前状态：

- Tauri 壳已接通。
- 当前包含占位命令 `ping_bridge` 和真实推理命令 `run_local_analysis`。
- `run_local_analysis` 支持两类图片输入：
  - 仓库内或本机上的图片路径
  - 前端上传图片，Rust 会先写入临时文件再调用 Python
- 当前仍未实现真正的流式 Stage 1 / Stage 2 事件桥接，前端进度条仍是阶段式状态反馈。

这意味着：

- 当前桌面版能作为本地 UI 壳运行。
- 并且已经可以作为真实本地推理客户端的最小版本运行。

## 13. 已知限制

### 13.1 纯静态网页部署不支持本地图像

如果把 `dist/` 直接作为静态网站发布：

- 浏览器没有权限直接读取仓库里的本地图片。
- 因此“仓库相对路径图片”方案在纯静态网站中不可用。

也就是说：

- `npm run dev` 可用
- `tauri:dev` / `tauri:build` 可用
- 纯静态公网部署若仍想显示这些本地图像，需要额外后端或预复制资源方案

### 13.2 样例图像依赖仓库完整性

如果 `data/processed/imgs/war_imgs_total/` 缺失，页面会有样例文本和结构化结果，但图片无法显示。

### 13.3 Tauri 尚未接入业务桥

当前桌面版适合作为展示壳，不适合作为最终推理交付版本。

## 14. 推荐后续开发方向

优先级建议：

1. 在 Tauri Rust 侧增加真实文件/命令桥。
2. 把 `analysis.ts` 的启发式逻辑替换为真实本地推理流。
3. 为图片路径解析增加更明确的错误提示。
4. 在桌面版中加入“仓库根目录自检”或“数据目录自检”。

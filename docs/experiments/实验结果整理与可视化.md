## 4. Stage 2 核心对比结果

### 4.1 Baseline: 直接拿 Stage1 adapter 做 Stage2

| 指标 | 数值 |
| --- | ---: |
| cue_present_macro_f1 | 0.3663 |
| cue_score_accuracy | 0.5719 |
| cue_score_mae | 0.6554 |
| relation_macro_f1 | 0.0000 |
| cue_reason_non_empty_rate | 0.0000 |
| consistency_reason_non_empty_rate | 0.0000 |

结论：

- 这个 baseline 很弱，尤其 relation 完全没有起效。
- 说明 Stage2 单独微调是必要的，不能指望 Stage1 adapter 直接迁移到 Stage2。

### 4.2 Stage2_v1: gold observations 条件下

| 指标 | 数值 |
| --- | ---: |
| matched_rows | 982 |
| failed_rows | 0 |
| cue_present_macro_f1 | 0.8417 |
| cue_score_accuracy | 0.7670 |
| cue_score_mae | 0.2643 |
| relation_macro_f1 | 0.5235 |
| cue_reason_non_empty_rate | 0.8927 |
| consistency_reason_non_empty_rate | 0.8900 |

结论：

- 这是目前本地效果最强、最稳定的一组结果。
- 相比 baseline，Stage2 微调明显提升了 cue 检测、score 预测和 relation 判断。

### 4.3 Stage2_v1: predicted observations 条件下

| 指标 | 数值 |
| --- | ---: |
| matched_rows | 983 |
| failed_rows | 17 |
| cue_present_macro_f1 | 0.7385 |
| cue_score_accuracy | 0.6585 |
| cue_score_mae | 0.4086 |
| relation_macro_f1 | 0.3365 |
| cue_reason_non_empty_rate | 0.8693 |
| consistency_reason_non_empty_rate | 0.8688 |

结论：

- 一旦输入从 gold observations 换成 predicted observations，Stage2_v1 指标显著下降。
- 降幅最明显的是 relation，从 `0.5235` 降到 `0.3365`。
- 这说明目前最主要的问题并不是 Stage2 本身不会学，而是 train / inference 分布不一致。

![stage2_comparison](outputs/analysis/stage2_comparison.png)

### 4.4 结果总结

从已有实验可以得到三个明确结论：

1. `stage2_v1 + gold obs` 是当前 strongest offline setup。
2. `stage2_v1 + predicted obs` 会明显退化，说明 distribution gap 确实存在。
3. 因此继续做 `stage2_v2` 和 `stage2_v3` 是有充分实验依据的。

- 若 Stage1 输出无法提取到合法 JSON，会触发 `ValueError: No valid JSON object found in model output`
- 这类失败说明 Stage1 上游推理稳定性仍然影响 Stage2 下游数据质量

## 7. 当前阶段建议

如果目标是追求更真实推理场景下的稳定性，我建议后续实验顺序如下：

1. 保留 `stage2_v1` 作为 gold obs 上限基线。
2. 跑 `stage2_v2`，验证纯 predicted obs 训练能否缩小推理分布差距。
3. 跑 `stage2_v3`，验证 `7:3` mixed training 是否能在鲁棒性和上限之间取得更好的平衡。

我目前的判断是：

- `v1` 更像上限参考
- `v2` 更像纯分布对齐方案
- `v3` 最有机会成为实际使用时的折中最优解
